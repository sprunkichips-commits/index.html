# Бэкенд «Деньги» — Cloudflare Worker + D1

Что уже сделано и проверено локально:

| Файл | Назначение |
|---|---|
| `wrangler.toml` (в корне) | конфиг деплоя: биндинг `DB` (D1) и `ASSETS` (статика) |
| `worker/schema.sql` | таблицы `categories` → `subcategories` → `transactions` + справочники |
| `worker/src/index.ts` | API на Hono: транзакции, категории, статистика |
| `worker/src/auth.ts` | проверка подписи Telegram `initData` |
| `worker/src/queries.ts` | агрегация сумм и процентов в SQL (считает база) |
| `src/lib/api.ts` | клиент API (пока не подключён к экранам) |
| `src/lib/useApiResource.ts` | хук состояний загрузки для UI |

## Эндпоинты

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/api/health` | проверка живости (без авторизации) |
| GET | `/api/categories` | справочник категорий и подкатегорий |
| GET | `/api/transactions?year=&month=` | операции за период (или `?from=&to=`) |
| POST | `/api/transactions` | добавить операцию |
| DELETE | `/api/transactions/:id` | удалить свою операцию |
| GET | `/api/stats?year=&month=` | итоги + источники дохода + расходы по категориям |
| GET | `/api/stats/subcategories?categoryId=` | разбивка категории по подкатегориям с % |
| GET | `/api/stats/monthly?year=` | помесячные итоги для графика |

Все пути кроме `/api/health` требуют заголовок `X-Telegram-Init-Data`.

## Ключевые решения

**Деньги хранятся в копейках целым числом** (`amount_cents`). Дробные суммы
не «плывут»: 100.50 + 50.25 = ровно 150.75.

**`user_id` берётся только из проверенной подписи Telegram**, никогда из тела
запроса. В каждом SQL-запросе есть `WHERE user_id = ?`, поэтому чужие данные
недоступны физически, а не «по договорённости».

**Транзит считается в SQL.** Если деньги прошли насквозь (дали 5000, 2700
передал дальше), в статистику попадает только чистый остаток 2300 — иначе
источник дохода раздувается ложной суммой. Чистый итог (доход − расход)
сохраняется точно, поэтому баланс кошелька не «плывёт».

## Проверено локально (без обращения к Cloudflare)

```
доход 12300 ₽ (10000 + чистые 2300 транзита, НЕ 15000)
расход 1500.50 ₽ (транзитные 2700 исключены)
баланс 10799.50 ₽
источники: YouTube 10000 (81.3%), Family 2300 (18.7%)
подкатегории Groceries: Meat 1500.50 (100%)

без initData          → 401
с поддельной подписью → 401
другой пользователь   → пустой список (чужие данные не видны)
```

## Настройки сборки в Cloudflare

В панели Cloudflare (Workers Builds → Settings → Build) должно быть:

| Поле | Значение |
|---|---|
| Build command | `VITE_BASE=/ npm run build` |
| Deploy command | `npx wrangler deploy` |
| Production branch | `main` |

`VITE_BASE=/` обязателен. Без него ассеты собираются с путём `/index.html/...`
(адрес GitHub Pages), на Cloudflare не находятся и открывается белый экран.
Cloudflare выставляет переменную `WORKERS_CI`, поэтому база переключается и
автоматически — переменная в команде нужна как надёжная подстраховка.

Сейчас деплоится **только статика**: блок `[[d1_databases]]` в `wrangler.toml`
закомментирован, приложение работает на локальном хранилище как раньше, а
`/api/*` отвечает `503 database_not_configured`. Это штатное состояние до
создания базы.

## Что нужно сделать тебе (по порядку)

Команды выполняются на **твоём компьютере** — из этой среды доступ к Cloudflare
закрыт сетевой политикой.

### 1. Создать базу

```bash
npx wrangler d1 create dengi-db
```

Команда напечатает `database_id`. Вставить его в `wrangler.toml` вместо
`PASTE_DATABASE_ID_HERE` и закоммитить.

### 2. Применить схему

```bash
npx wrangler d1 execute dengi-db --remote --file=worker/schema.sql
```

### 3. Положить токен бота в секреты

Токен берётся у @BotFather. **Не вписывать его в файлы** — репозиторий публичный.

```bash
npx wrangler secret put BOT_TOKEN
```

### 4. Первый деплой

```bash
npm run build && npx wrangler deploy
```

### 5. Проверить

Открыть `https://<адрес-воркера>/api/health` — должен ответить `{"ok":true}`.

## Важно перед переключением фронтенда

1. **`base` в `vite.config.ts`** сейчас `/index.html/` — это путь GitHub Pages.
   Для Cloudflare нужно `/`, иначе стили и скрипты не найдутся.
2. **Перенос данных.** Финансы и цели лежат в Telegram CloudStorage. Перед
   отключением локального хранилища нужно перелить их в D1, иначе история
   пропадёт с экрана. Порядок: выгрузить бэкап (Настройки → Download file) →
   импортировать в базу → сверить суммы → только потом переключать клиент.
3. **Два деплоя одновременно.** Пока `main` собирается и на GitHub Pages, и на
   Cloudflare. После переезда старый workflow (`.github/workflows/deploy.yml`)
   нужно отключить, чтобы не было двух разных версий приложения.
4. **Цели и инвестиции** в схему пока не переносились — только категории,
   подкатегории и транзакции, как в задании. Это отдельный шаг.

## Локальная разработка

```bash
npx wrangler d1 execute dengi-db --local --file=worker/schema.sql
npx wrangler dev --local --var ALLOW_DEV_USER:777001
```

`ALLOW_DEV_USER` подменяет авторизацию фиктивным пользователем. Переменная
работает только если её явно передать — в боевом окружении её нет.
