# Перенос данных в облако

Инструкция на один раз: как забрать историю из старого приложения и убедиться,
что в новом она на месте — без потерь и без дублей.

Отправлять один и тот же файл можно сколько угодно раз: сервер узнаёт уже
перенесённые записи по их id и не создаёт копии. В отчёте они попадают в строку
«already there».

---

## Шаг 1. Выгрузить файл из старого приложения

Открыть **старое** приложение — то, где сейчас видна вся история
(через бота в Телеграме, адрес `…github.io/index.html/`).

1. Значок настроек (шестерёнка) в правом верхнем углу.
2. Раздел **Backup** → кнопка **Download file**.
3. Сохранится файл `dengi-backup-2026-07-26.json`. Его не открывать и не
   править — он нужен целиком.

В файле лежит всё: операции, подкатегории, заметки, «от кого» у доходов,
транзит, цели, ежедневные задачи с отметками по дням и профиль (ник, аватар).

> Цели раньше жили только на устройстве и в зашифрованном виде. В файл они
> попадают уже расшифрованными, поэтому выгрузку нужно делать из того
> приложения, где цели видны на экране. Если во вкладке «Цели» пусто —
> подождать пару секунд и нажать Download file снова.

## Шаг 2. Загрузить файл в новое приложение

Открыть **новое** приложение на адресе Cloudflare — в браузере или через бота.

1. Настройки → раздел **Cloud storage**.
2. Кнопка **Load backup file into cloud** → выбрать сохранённый `.json`.
3. Дождаться отчёта «Uploaded».

На сайте в браузере сначала появится кнопка входа через Телеграм — войти нужно
тем же аккаунтом, иначе сервер не поймёт, чьи это данные, и покажет
«Telegram authorization failed».

Старое приложение при этом не меняется: перенос копирует данные, а не забирает.
Файл лучше сохранить — это же и обычный бэкап.

---

## Шаг 3. Проверить, что ничего не потерялось

Проверка построена так, чтобы не верить на слово: сравниваются конкретные числа,
которые видно на экране в обоих приложениях.

### 3.1 Отчёт сразу после загрузки

При **первой** загрузке в пустую базу отчёт должен показать:

| Строка | Ожидается |
| --- | --- |
| Transactions | **98 new** |
| Goals | **1 new** |
| Daily tasks | **3 new** |
| Check-ins | **11 new** (отметки за 7 дней) |
| Profile | **transferred** |

`skipped` везде должен быть **0**. Если там не ноль — какая-то запись не прошла
проверку; ниже в отчёте будет написано, какая именно.

При повторной загрузке того же файла все те же числа переедут в столбец
«already there», а «new» станет нулём. Это норма и признак того, что дублей нет.

### 3.2 Итоги месяца — главная проверка

Открыть **июль 2026** в старом и новом приложении и сравнить три числа на
вкладке Stats:

| Показатель | Должно быть |
| --- | --- |
| Доход | **42 792 ₽** |
| Расход | **17 402,73 ₽** |
| Остаток | **+25 389,27 ₽** |

Копейки в расходе — самая чувствительная проверка: если где-то теряется
округление, `17 402,73` превратится в `17 402` или `17 403`. Должно совпадать
до копейки.

### 3.3 Откуда пришли деньги

| Источник | Сумма | Доля |
| --- | --- | --- |
| Day job | 32 000 ₽ | 75 % |
| Family | 6 800 ₽ | 16 % |
| Other income | 3 992 ₽ | 9 % |

Сумма трёх строк = 42 792 ₽, то есть ровно доход из пункта 3.2.

Отдельно про транзит: 5 000 ₽ получено и 2 700 ₽ передано дальше. В доходах
должно стоять **не 5 000**, а остаток 2 300 ₽ — при нажатии на источник видно
пояснение «5 000 ₽ received − 2 700 ₽ passed on». Если где-то всплыло 5 000 —
транзит перенёсся как обычный доход, и это надо показать мне.

### 3.4 Куда уходят деньги

| Категория | Сумма | Доля |
| --- | --- | --- |
| Groceries | 7 954,73 ₽ | 46 % |
| Subscriptions | 3 623 ₽ | 21 % |
| Transport | 3 371 ₽ | 19 % |
| Education | 1 284 ₽ | 7 % |
| Entertainment | 1 170 ₽ | 7 % |

Сумма пяти строк = 17 402,73 ₽ — расход из пункта 3.2.

### 3.5 Подкатегории, заметки, «от кого»

- Нажать на **Groceries** — внизу открывается разбивка по подкатегориям
  (Meat / Water / Snacks / без подкатегории). Ровно **одна** операция лежит в
  подкатегории, остальные — в «без подкатегории».
- Нажать на **Family** в доходах — у **одной** операции подписано, от кого
  пришли деньги (поле «от кого» из старого приложения).
- Заметки: **две** операции с заметками. Видны при нажатии на операцию в списке.

### 3.6 Цели

Вкладка «Цели»:

- цель **«New life»** со сроком **18 февраля 2027**;
- три ежедневных пункта: Английский, чтение, ютуб;
- график за 7 дней рисует те же отметки, что и в старом приложении: всего
  перенеслось **11 отметок за 7 дней**. Сравнить два-три дня наугад — нажать на
  день и посмотреть, какие пункты отмечены выполненными.

### 3.7 Профиль

Ник **Максим** и аватар на месте в шапке.

## Если что-то не сходится

- **Все числа нулевые, в шапке «Guest»** — вход не выполнен. В браузере нужно
  нажать кнопку входа через Телеграм; в Телеграме — открыть приложение из бота,
  а не по ссылке в браузере.
- **Кнопки входа на сайте нет вообще** — на сервере не задана переменная
  `BOT_USERNAME` (имя бота без `@`). Это открытая настройка, не секрет; добавить
  её в переменные Worker'а и пересобрать.
- **«This copy of the app is opened from the old address…»** — открыт старый
  адрес GitHub Pages. Он умеет отдавать только файлы и в облако не пишет; нужно
  открыть адрес Cloudflare (и поменять ссылку у бота в BotFather).
- **«Database is not connected on the server yet»** — к Worker'у не привязана
  база D1.
- **Числа разошлись** — ничего не удалять и не загружать повторно, а показать
  мне отчёт и оба экрана Stats. Старые данные при этом целы: перенос только
  добавляет.
